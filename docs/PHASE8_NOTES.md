# Phase 8 Notes — Real-Time Dashboard (Visualization)

## What this phase produced

### Streamlit Application (`dashboard/`)
1. **`app.py`**: The entry point for the visualizer. It caches and loads the JSON/CSV results generated by the Phase 7 End-to-End Evaluation pipeline from `results/tables/`. It displays the Pandas dataframes natively in the browser for easy tabular reading.
2. **`components/charts.py`**: Contains the modular Plotly chart functions:
   - `render_coverage_over_time()`: Parses the deep snapshots from `raw_results.json` into a continuous line graph showing exactly how fast AI-Guided exploration reaches 100% coverage vs traditional DFS/BFS.
   - `render_heuristic_comparison()`: Uses the aggregate `metrics_table.csv` to generate grouped bar charts (configurable to show Coverage, Bugs Found, Execution Time, or Unique Paths).
   - `render_live_execution_tree_mock()`: Prepares the UI infrastructure for Phase 10 where the live C++ KLEE bindings will stream websocket events to draw the active execution forks. Currently uses static mock data.

## Architecture Context

Why Streamlit?
Streamlit is perfectly suited for Python-heavy data science pipelines. Rather than building a sprawling React frontend with REST endpoints, Streamlit allows us to directly import our Pydantic schemas and Pandas DataFrames, dramatically reducing boilerplate and keeping the focus on the research results.

By decoupling the evaluation execution (Phase 7) from the visualization (Phase 8) using JSON/CSV interchange files, we ensure that long-running symbolic execution tasks can run headlessly on a Linux server, and the dashboard can be loaded instantaneously on a laptop without re-running the heavy workloads.

## Running the Dashboard
1. Ensure the Python environment has `streamlit` and `plotly` installed:
   ```bash
   pip install streamlit plotly
   ```
2. Run the dashboard from the project root:
   ```bash
   streamlit run dashboard/app.py
   ```
